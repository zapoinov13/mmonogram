# Модели конфигуратора

Оцифрованные модели G63 в формате GLB со сжатием Draco. Какой файл к чему
относится, задаёт `src/components/configurator/models.ts` — этот список лишь
пересказывает его. К адресу каждого файла рендерер дописывает `?v=…`
(`modelAssetUrl`): после замены модели версию надо поднять, иначе браузеры
останутся на закэшированной старой.

## Студийная сборка — грузится по умолчанию, около 23 МБ

Полный CAD-салон с приборами и консолью:

| Файл | Что внутри |
|---|---|
| `body-studio.glb` | кузов |
| `kit-grille-refined.glb` | обвес и решётка |
| `cabin-tailored.glb` | каркас салона |
| `cabin-upholstery.glb` | обивка |
| `dashboard-studio.glb` | передняя панель |
| `console-original.glb` | центральная консоль |
| `instruments-original.glb` | приборы |
| `steering-details.glb` | детали руля |
| `parts/steering-wheel.glb` | руль |
| `wheels-finished.glb` | колёса (для варианта «ICONIC Original») |

Руль вынесен отдельным файлом: так можно менять качество этой заметной детали,
не переэкспортируя весь салон. В рендерере старая геометрия в зоне руля
маскируется, чтобы не было наложения двух деталей.

## Лёгкий набор — только по `?cad=0`, около 10 МБ

Прореженные выгрузки прошлого поколения, оставлены как запасной вариант:
`body-refined.glb`, `kit-refined.glb`, `interior-refined.glb`,
`parts/steering-wheel.glb`.

## Тяжёлые исходники — только по `?hq=1`, около 65 МБ

Сами не грузятся, нужны для сравнения геометрии: `parts/stock-body.glb`,
`parts/body-kit-wheels.glb`, `parts/custom-interior.glb`.

## Исходники конвейера — лежат здесь же, на сайт не нужны

`body-clean.glb`, `cad-interior-web.glb`, `cabin-structure.glb`,
`dashboard-original.glb`, `wheels-original.glb` — промежуточные ступени,
из которых `scripts/prepare-studio-assets.ts`, `finish-cabin.mjs` и
`finish-original-wheels.mjs` собирают студийный набор; их же читают тесты
`npm run test:configurator`. Сюда же относятся `cad-steering-center.glb` и
`cad-steering-controls.glb`: сайт их не грузит, но `cad-interior.test.ts`
держит на них бюджет размера и состав деталей руля. Сайт эти файлы не запрашивает, но из `public`
они уезжают на домен вместе со всем остальным — про это и предупреждает
`check:configurator`. Это осознанная цена: скрипты и тесты ждут их по этим
путям. Решите выносить — двигайте вместе с путями во всех скриптах разом.

## Как готовятся файлы

Исходные FBX конвертируются так:

```
/Applications/Blender.app/Contents/MacOS/Blender --background \
    --python scripts/fbx-to-glb.py -- <папка-с-fbx> public/models \
    --max-tris 700000 --only "body kit"
```

Тяжёлые модели гоняются по одному ключом `--only`: децимация держит всю сетку
в памяти, и на 8 ГБ система убивает процесс молча. Прореживание идёт молча по
несколько минут — не прерывайте его и ничего не вводите в то же окно
терминала.

Прореживать надо до сжатия, а не после: чтобы прорезать готовый GLB,
`gltf-transform` распаковывает Draco в WebAssembly, и на сотне мегабайт сжатой
геометрии этот модуль падает независимо от размера heap у Node.

Готовый GLB кладётся в `public/models` целиком: папка копируется в сборку как
есть, поэтому файл, на который никто не ссылается, всё равно уезжает на домен.
Проверить, что таких не осталось, — `npm run check:configurator`.

Структуру готового GLB — меши, полигоны, материалы, габариты — показывает
`node scripts/inspect-glb.mjs public/models/*.glb`.
